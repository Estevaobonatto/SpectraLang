Uma linguagem deve soar como uma ideia clara.

Esta segunda versão propõe uma superfície mais próxima de uma linguagem de alto nível: menos pontuação estrutural, nomes de construção mais descritivos e uma única forma canônica para cada decisão.

from std.collections import length

    id: Integer

    paid: Boolean = false

Documento de design. As formas propostas são simuladas e não alteram o parser atual.

01

O problema não é poder. É esforço de leitura.

A sintaxe atual é expressiva e cobre uma base sólida de linguagem, mas sua aparência é marcada por decisões de sistemas. Para quem lê código como descrição de negócio, cada abreviação e cada variação cobra uma pequena taxa mental.

Diagnóstico

Spectra já tem os ingredientes de uma linguagem de alto nível: inferência local, blocos como expressão, async/await, tipos agregados e pattern matching. A mudança recomendada é de superfície e coerência: fazer a primeira leitura funcionar para alguém que não precise pensar em Rust, parser ou AST.

hoje compacta e Rust-like
proposta descritiva e linear
hoje várias grafias possíveis
proposta uma grafia canônica
hoje blocos com pontuação
proposta blocos com palavras
02

Seis regras para a leitura humana.

A proposta não tenta transformar código em prosa artificial. Ela reduz decisões acidentais e deixa as decisões importantes explícitas.

R1

Uma ideia, uma palavra

Escolher else if, não manter elif e elseif como sinônimos. Escolher for ... in, não duplicar com of.

R2

O bloco fala por si

Usar chaves para encerrar funções, condições, loops e tipos. A quebra de linha encerra instruções e a indentação continua sendo estilo, não uma regra invisível do parser.

R3

A mutação é um verbo

let declara valores e a atribuição direta torna a alteração visível. O leitor não precisa aprender uma palavra nova para cada mudança de estado.

R4

Declarações se leem como títulos

Preferir func, record, public e impl na superfície principal. Abreviações podem existir como compatibilidade.

R5

Tipos aparecem onde decidem

Inferir variáveis locais, mas declarar tipos em APIs, records e retornos públicos. Isso mantém o código curto sem esconder contratos.

R6

Palavras antes de glifos

Preferir returns, and, or e not quando isso melhora a leitura. Os operadores simbólicos podem permanecer como forma curta para código numérico.

03

O novo contrato de superfície.

Estas são as mudanças que mais aproximam a linguagem de um ambiente high-level. A coluna de impacto existe para deixar claro que legibilidade também tem custo de implementação.

nível decisão forma proposta por que vale
P0
Blocos sem pontuação

Remover ponto e vírgula da forma canônica.

func ... returns Text { ... }

O olho acompanha a estrutura sem contar chaves.

P0
Declarações completas

Adicionar palavras descritivas como forma principal.

public func · record · impl

O leitor entende a intenção antes dos detalhes.

P0
Import em ordem natural

Colocar origem antes dos nomes importados.

from std.io import println

Reduz a inversão mental de módulo e símbolo.

P0
Mutação explícita

Separar criação de alteração.

let total = 0 · total = total + value

Leitura local revela quando o estado muda.

P1
Match verbal

Unificar ramificações com when e otherwise.

match value · when Pending · otherwise

Pattern matching fica menos parecido com tabela de tokens.

P1
Negação previsível

Retirar unless da escrita recomendada.

if not condition

Há um único caminho para entender condições negativas.

P1
Tipos de alto nível

Oferecer aliases semânticos para tipos básicos e coleções.

Integer · Text · List<Order>

Assinaturas comunicam domínio, não representação.

P2
Interpolação natural

Tratar interpolação como comportamento padrão de texto.

"Total: {total}" · raw"..."

Mensagens deixam de carregar um prefixo técnico.

01 · módulo e imports

origem antes do símbolo
atual
module orders
import { println, length } from std.io
import std.orders as orders_api
proposta humana
module orders

from std.io import println, length
from std.orders import api as orders_api

Hoje: a palavra import aparece antes de descobrir a origem ou depois de uma lista de nomes.

Depois: a frase começa pela fonte e termina no que será usado.

02 · função pública assíncrona

declaração como título
atual
pub async fn list_orders(
    user_id: int
) -> [Order] {
    let orders = await repository.all(user_id)
    orders
}
proposta humana
public async func list_orders(
    user_id: Integer
) returns List<Order> {
    let orders = await repository.all(user_id)
    return orders
}

Hoje: pub, fn e -> são eficientes, mas exigem vocabulário prévio.

Depois: a assinatura pode ser lida como “função pública retorna lista”.

03 · criação versus alteração

mutação como verbo
atual
let total = 0
for order in orders {
    total = total + order.amount
}
proposta humana
let total = 0
for order in orders {
    total = total + order.amount
}

Hoje: o leitor descobre a mutabilidade olhando usos posteriores.

Depois: a atribuição direta marca cada mudança de estado sem criar uma palavra nova.

04 · condição sem aliases

uma leitura linear
atual
if score > 90 {
    grade = "A"
} elif score > 60 {
    grade = "B"
} else {
    grade = "C"
}
proposta humana
if score > 90 {
    grade = "A"
} else if score > 60 {
    grade = "B"
} else {
    grade = "C"
}

Hoje: elif e elseif competem com else if na documentação e no editor.

Depois: a estrutura aparece como três frases e termina em um marcador explícito.

05 · loop e negação

vocabulário previsível
atual
unless orders.is_empty() {
    for item of orders {
        print(item)
    }
}
proposta humana
if not orders.is_empty() {
    for item in orders {
        print(item)
    }
}

Hoje: há duas decisões independentes para lembrar: unless e of.

Depois: condições negativas e iteração usam palavras únicas e familiares.

06 · match como decisão legível

when / otherwise
atual
let label = match status {
    Status::Pending => "aguardando"
    Status::Paid => "pago"
    _ => "desconhecido"
}
proposta humana
let label = match status {
    when Pending then "aguardando"
    when Paid then "pago"
    otherwise "desconhecido"
}

Hoje: a seta e o wildcard são concisos, mas visualmente próximos de uma tabela interna do compilador.

Depois: cada caso se lê como uma condição. otherwise comunica a intenção.

07 · dados e comportamento

record / impl
atual
struct User {
    name: string
    active: bool
}

impl User {
    fn label(&self) -> string {
        self.name
    }
}
proposta humana
record User {
    name: Text
    active: Boolean
}

impl User {
    func label(self) returns Text {
        return self.name
    }
}

Hoje: struct e impl são termos de uma família específica de linguagens.

Depois: o código diferencia “registro de dados” e “comportamento implementado”.

08 · texto interpolado

string por padrão
atual
let message = f"Total: {total} e pedidos: {count}"
proposta humana
let message = "Total: {total} e pedidos: {count}"
# use raw"..." somente quando não quiser interpolação

Hoje: o prefixo f é uma pista técnica que todo texto dinâmico precisa carregar.

Depois: a forma mais comum é a mais simples. O caso especial ganha um marcador explícito.

05

Como ficaria um módulo completo.

O exemplo combina as decisões sem inventar uma nova linguagem de domínio. Ainda é código. A diferença é que a leitura principal não depende de símbolos compactos. 

module billing

from std.collections import length

record Order {
    id: Integer
    customer: Text
    amount: Decimal
    paid: Boolean = false
}

public async func list_open_orders(
    customer: Text
) returns List<Order> {
    let orders = await repository.all_orders(customer)
    let open_orders = []

    for order in orders
    if not order.paid {
        add open_orders, order
    }

    return open_orders
}

public func summarize(
    orders: List<Order>
) returns Text {
    let total: Decimal = 0

    for order in orders {
        total = total + order.amount
    }

    return "Total: {total} e pedidos: {length(orders)}"
}

O que fica óbvio

O módulo importa, declara dados, expõe funções, busca valores e altera somente o estado marcado.

O que continua técnico

Tipos genéricos, async/await, chamadas de método e operações ainda são explícitos para não esconder o custo real.

O que é proposta

Decimal, List<T>, add e a interpolação sem prefixo precisam de contrato de biblioteca e parser.

06

Legibilidade não elimina trade-offs.

A superfície sugerida privilegia o leitor. O design só é bom se as consequências para parser, diagnósticos, formatter e compatibilidade ficarem visíveis desde o início.

chaves versus indentação

ganho

Chaves são familiares, fecham o bloco visualmente e não criam uma nova palavra estrutural.

custo

O leitor ainda vê pontuação de bloco e o formatter precisa cuidar do alinhamento.

decisão

Manter chaves para blocos e deixar a quebra de linha encerrar instruções sem um terminador extra.

let e atribuição direta

ganho

A mesma forma serve para declarar e atualizar um valor, sem espalhar vocabulário pela linguagem.

custo

É preciso documentar claramente a mutabilidade atual e usar lint para sugerir valores que não mudam.

decisão

Preservar a semântica atual de let e tornar a atribuição em linha a forma recomendada.

palavras versus símbolos

ganho

returns, and e not podem ser lidos sem consultar uma tabela de operadores.

custo

Mais palavras viram keywords e podem colidir com identificadores de projetos antigos.

decisão

Oferecer palavras como forma canônica e preservar símbolos em expressões numéricas.

when versus operadores de seta

ganho

Cases parecem frases condicionais, e otherwise é autoexplicativo.

custo

Pattern matching precisa manter exaustividade, guards e expressão de cauda.

decisão

Mapear a nova sintaxe para o AST de match, sem criar um segundo modelo de controle.

07

Migração sem quebrar a linguagem.

A superfície pode mudar em camadas. O ponto central é manter uma única verdade semântica no AST e fazer o formatter orientar o ecossistema para a forma humana.

F1 · aceitar

Aliases de entrada

O lexer/parser aceitam func, record, public, returns e o novo import, baixando tudo para os nós existentes.

F2 · formatar

Uma saída oficial

spectralang fmt imprime a forma humana, remove terminadores artificiais e escolhe sempre else if, for ... in e match.

F3 · orientar

Avisos úteis

O compilador e o LSP avisam quando o código usa a grafia antiga, mostram a substituição e preservam a posição do diagnóstico.

F4 · simplificar

Remover duplicidade

Só depois de documentação, examples, testes e tooling migrarem, deprecar elif, elseif, of, unless e aliases incompatíveis.

Regra de segurança: a nova superfície não deve criar um segundo compilador. Sintaxe humana é apenas outra entrada para o mesmo AST, semântica, lowering e backend.

08

O que não deve ser sacrificado.

“High-level” não precisa significar uma linguagem vaga ou excessivamente natural. A clareza deve conviver com contratos verificáveis e com o desempenho do backend atual.

+

Inferência local

Manter declarações curtas quando o tipo é evidente. Exigir contratos em fronteiras públicas.

+

async/await

As palavras já são compreensíveis e dão visibilidade ao custo de esperar uma operação.

+

match exaustivo

A segurança do pattern matching deve continuar. Apenas a forma de escrever cases fica mais verbal.

+

expressões de cauda

Podem permanecer para funções pequenas, mas o formatter e o lint devem sugerir return em APIs.

+

literais familiares

Parênteses, colchetes e chaves continuam úteis para chamadas, listas e records. O alvo são blocos, não todos os símbolos.

+

sem prosa mágica

Evitar frases livres, indentação obrigatória e keywords que tentem adivinhar a intenção do autor.

09

Gates para chamar isso de pronto.

Legibilidade é uma propriedade da experiência inteira, não só do parser. Cada etapa abaixo precisa acompanhar a mudança.

Lexer

Keywords novas, palavras compostas e terminadores de bloco preservam spans e comentários.

token tests + diagnostics

Parser / AST

As duas grafias produzem os mesmos nós. Chaves não podem alterar precedência nem retorno de cauda.

parser fixtures + snapshots

Semântica

let e atribuições diretas têm regras claras para escopo, closures, imports e usos inválidos.

semantic regressions

Midend / backend

Funções, loops, match, async e records high-level executam pelo caminho normal do CLI.

run + integrated fixtures

Formatter / LSP

O formatter escolhe uma saída única. Hints, completions, hover e diagnósticos mostram a nova nomenclatura.

formatter + language service

Ecossistema

README, referência, examples, syntax highlighting e pacotes públicos usam a superfície recomendada.

docs parity audit

De onde veio a análise.

A proposta foi montada sobre a implementação existente, não sobre uma linguagem hipotética. Estes pontos são as fontes para validar cada decisão antes de transformá-la em código.

Como interpretar “proposta” neste documento

func, record, impl, chaves, when, otherwise, from ... import ... e os aliases de tipo são decisões de design. A implementação atual continua sendo a autoridade sobre o que compila hoje. Antes de promover qualquer item, a mudança deve ganhar regressões no frontend e uma prova de execução pelo caminho normal.
